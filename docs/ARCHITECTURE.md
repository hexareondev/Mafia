# Техническая архитектура

## Цель первой версии

Сделать браузерную игру для закрытых компаний друзей, в которой сервер полностью управляет ходом партии. Отдельный ведущий не требуется.

## Структура репозитория

- `apps/web` — React-интерфейс на TypeScript, сборка Vite.
- `apps/server` — Node.js, Express и Socket.IO. Сервер является авторитетным источником игрового состояния.
- `packages/shared` — общие типы событий и DTO для клиента и сервера.
- `docs` — технические решения и документация разработчика.

## Локальный запуск

Требуется Node.js 20 или новее.

1. Выполнить `npm install` в корне репозитория.
2. Выполнить `npm run dev`.
3. Открыть `http://localhost:5173`.

Клиент по умолчанию подключается к серверу на `http://localhost:3001`. Для другого адреса задаётся `VITE_SERVER_URL`. Сервер принимает `CLIENT_ORIGIN` и `PORT`.

## Принципы

- Сервер — единственный источник истины для комнат, ролей, таймеров, голосований и исходов партии.
- Клиент получает только данные, которые разрешено видеть конкретному игроку.
- Все входящие действия валидируются на сервере: текущая фаза, роль, право на действие и повторные запросы.
- Секретные роли и приватные действия никогда не рассылаются в общую комнату Socket.IO.
- Игровая логика должна быть отделена от транспортного слоя Socket.IO, чтобы её можно было тестировать независимо.

## Текущий MVP

Реализованы создание комнаты, вход по коду, список игроков, передача хоста при выходе создателя и удаление пустой комнаты. Комнаты пока хранятся в памяти процесса: перезапуск сервера удаляет их. Запуск партии, роли, игровые фазы и постоянное хранение данных ещё не реализованы.

## Следующие этапы

1. Валидация и тесты комнат, ограничения частоты запросов и защита от некорректных состояний.
2. Модель партии и конфигурация ролей для разного количества игроков.
3. Автоматический игровой цикл: ночь, действия ролей, день, обсуждение, голосование, проверка победы.
4. Приватная доставка ролей и действий, reconnect/resume.
5. История партий, профили и постоянное хранилище.
