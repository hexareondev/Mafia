# Техническая архитектура

## Цель первой версии

Сделать браузерную игру для закрытых компаний друзей, в которой сервер полностью управляет ходом партии. Отдельный ведущий не требуется.

## Структура репозитория

- `apps/web` — React-интерфейс на TypeScript, сборка Vite.
- `apps/server` — Node.js, Express и Socket.IO. Сервер является авторитетным источником игрового состояния.
- `packages/shared` — общие типы событий и DTO для клиента и сервера.
- `docs` — технические решения и документация разработчика.

## Локальный запуск

Требуется Node.js 20 или новее.

1. Выполнить `npm install` в корне репозитория.
2. Выполнить `npm run dev`.
3. Открыть `http://localhost:5173`.

Клиент по умолчанию подключается к серверу на `http://localhost:3001`. Для другого адреса задаётся `VITE_SERVER_URL`. Сервер принимает `CLIENT_ORIGINS` (список разрешённых origin через запятую; для совместимости поддерживается и `CLIENT_ORIGIN`) и `PORT`.

## Публикация

### Клиент — GitHub Pages

Workflow `.github/workflows/deploy-pages.yml` собирает клиент и публикует его на GitHub Pages при каждом push в `main`.

1. В настройках репозитория открой **Settings → Pages** и выбери **Source: GitHub Actions**.
2. После создания сервиса на Render добавь в **Settings → Secrets and variables → Actions → Variables** переменную репозитория `VITE_SERVER_URL` со значением публичного URL сервера, например `https://mafia-server.onrender.com` (используй фактический адрес Render).
3. Запусти workflow **Deploy web to GitHub Pages** вручную или отправь новый commit в `main`.

Ожидаемый адрес сайта: `https://hexareondev.github.io/Mafia/`.

### Сервер — Render

Файл `render.yaml` описывает Node web service. В Render выбери **New → Blueprint**, подключи этот репозиторий и подтверди создание сервиса. Render установит зависимости, соберёт shared package и сервер, затем запустит Node.js приложение. Переменная `PORT` предоставляется платформой автоматически.

Проверка работоспособности: открыть `https://<имя-сервиса>.onrender.com/health`; ожидается JSON `{"status":"ok","service":"mafia-server"}`.

CORS разрешает origin GitHub Pages и локальный Vite. Если будет использоваться другой домен, обнови `CLIENT_ORIGINS` в настройках Render.

> Важно: комнаты сейчас хранятся в памяти процесса. Перезапуск или сон/пробуждение бесплатного сервиса может удалить все открытые комнаты. Для долгоживущих комнат понадобится внешнее хранилище и отдельная работа с reconnect.

## Принципы

- Сервер — единственный источник истины для комнат, ролей, таймеров, голосований и исходов партии.
- Клиент получает только данные, которые разрешено видеть конкретному игроку.
- Все входящие действия валидируются на сервере: текущая фаза, роль, право на действие и повторные запросы.
- Секретные роли и приватные действия никогда не рассылаются в общую комнату Socket.IO.
- Игровая логика должна быть отделена от транспортного слоя Socket.IO, чтобы её можно было тестировать независимо.

## Текущий MVP

Реализованы создание комнаты, вход по коду, список игроков, передача хоста при выходе создателя и удаление пустой комнаты. Комнаты пока хранятся в памяти процесса: перезапуск сервера удаляет их. Запуск партии, роли, игровые фазы и постоянное хранение данных ещё не реализованы.

## Следующие этапы

1. Валидация и тесты комнат, ограничения частоты запросов и защита от некорректных состояний.
2. Модель партии и конфигурация ролей для разного количества игроков.
3. Автоматический игровой цикл: ночь, действия ролей, день, обсуждение, голосование, проверка победы.
4. Приватная доставка ролей и действий, reconnect/resume.
5. История партий, профили и постоянное хранилище.
