# Техническая архитектура

## Цель первой версии

Сделать браузерную игру для закрытых компаний друзей, в которой сервер полностью управляет ходом партии. Отдельный ведущий не требуется.

## Структура репозитория

- `apps/web` — React-интерфейс на TypeScript, сборка Vite.
- `apps/server` — Node.js, Express и Socket.IO. Сервер является авторитетным источником игрового состояния.
- `packages/shared` — общие типы событий и DTO для клиента и сервера.
- `docs` — технические решения и документация разработчика.

## Локальный запуск

Требуется Node.js 20 или новее.

1. Выполнить `npm install` в корне репозитория.
2. Выполнить `npm run dev`.
3. Открыть `http://localhost:5173`.

Клиент по умолчанию подключается к серверу на `http://localhost:3001`. Для другого адреса задаётся `VITE_SERVER_URL`. Сервер принимает `CLIENT_ORIGINS` (список разрешённых origin через запятую; для совместимости поддерживается и `CLIENT_ORIGIN`) и `PORT`.

## Публикация

### Клиент — GitHub Pages

Workflow `.github/workflows/deploy-pages.yml` собирает клиент и публикует его на GitHub Pages при каждом push в `main`.

1. В настройках репозитория открой **Settings → Pages** и выбери **Source: GitHub Actions**.
2. После создания сервиса на Render добавь переменную репозитория `VITE_SERVER_URL` со значением публичного URL сервера. Для постоянного хранения создай Redis/Key Value instance у провайдера, затем добавь его connection URL в переменную окружения сервиса Render `REDIS_URL` (Blueprint запросит значение при настройке).
3. Запусти workflow **Deploy web to GitHub Pages** вручную или отправь новый commit в `main`.

Ожидаемый адрес сайта: `https://hexareondev.github.io/Mafia/`.

### Сервер — Render

Файл `render.yaml` описывает Node web service. В Render выбери **New → Blueprint**, подключи репозиторий и подтверди создание сервиса.

Проверка работоспособности: открыть `https://<имя-сервиса>.onrender.com/health`; ожидается JSON `{"status":"ok","service":"mafia-server"}`.

По умолчанию комнаты хранятся в памяти процесса. Если задан `REDIS_URL`, сервер подключает Redis и сохраняет сериализованное состояние комнат (включая роли и голоса) с TTL 7 дней; при запуске сохранённые комнаты загружаются, а игровые таймеры продолжаются. Без `REDIS_URL` приложение работает как прежде. Endpoint `/health` возвращает `storage: "redis"` или `storage: "memory"`, поэтому режим хранения можно проверить без доступа к логам. При кратком обрыве связи Socket.IO пытается восстановить соединение в течение двух минут. **Важно о бесплатном Render Key Value:** бесплатный план не поддерживает сохранение данных на диск, поэтому Redis-данные могут исчезнуть при перезапуске или обновлении самого хранилища. Для настоящей долговременной сохранности выбери платный план с режимом `Journal + Snapshot` либо другой Redis/Valkey-провайдер с включённой персистентностью. Бесплатный план подходит для проверки подключения, но не как надёжная база партий.

Каждый игрок получает постоянный UUID и случайный 256-битный токен возврата. Клиент хранит токен только в localStorage, сервер сохраняет в Redis только SHA-256 хеш токена. После перезапуска сервер сбрасывает устаревшие Socket.IO ID, а игрок может восстановить место, роль и команду мафии через событие `room:rejoin`. Токен является секретом: его нельзя публиковать или передавать другим игрокам.

## Логика лобби и ролей

- Комната находится в состоянии `lobby`, `playing` или `finished`.
- Игроки отмечают готовность; начать игру может только создатель комнаты, когда готовы все игроки.
- Для старта нужно минимум 4 игрока. Комната вмещает до 12 игроков.
- Сервер случайно распределяет роли: мафия, доктор, комиссар и мирные жители. На 10–12 игроков назначаются две мафии, на остальных составах — одна.
- Общий снимок комнаты не содержит ролей. Каждому игроку роль отправляется отдельным приватным Socket.IO-событием.
- После старта начинается первая ночь. Мафия выбирает цель (при нескольких мафиози учитывается большинство, ничья разрешается случайно), доктор выбирает игрока для спасения, комиссар проверяет игрока и получает результат приватно.
- Ночь длится до 60 секунд (настраивается через `NIGHT_DURATION_SECONDS`) и завершается раньше, если все живые специальные роли выполнили действия. При тайм-ауте отсутствующие действия считаются пропущенными; уже поданные голоса мафии учитываются. Убитый игрок помечается выбывшим; доктор может спасти в том числе себя. Повторное действие за одну ночь запрещено.
- После разрешения ночи наступает дневная фаза: игроки могут обсуждать партию в общем чате и один раз проголосовать за живого игрока (за себя голосовать нельзя). Голос нельзя изменить.
- День длится до 180 секунд (настраивается через `DAY_DURATION_SECONDS`) и завершается раньше, если все живые игроки проголосовали. При тайм-ауте учитываются только уже поданные голоса; при отсутствии голосов или ничьей никто не выбывает. При ничьей никто не выбывает. Затем сервер проверяет победу и, если партия продолжается, автоматически начинает следующую ночь.
- Чат доступен живым игрокам во время партии; последние 40 сообщений хранятся в состоянии комнаты.
- При кратком сетевом отключении игрок не удаляется сразу: включено восстановление Socket.IO с окном в две минуты. При восстановлении клиент получает актуальный снимок комнаты и свою приватную роль.
- Победа города наступает, когда мафии не осталось; победа мафии — когда число мафиози сравнялось с числом остальных живых игроков или превысило его.

## Принципы

- Сервер — единственный источник истины для комнат, ролей, таймеров, голосований и исходов партии.
- Клиент получает только данные, которые разрешено видеть конкретному игроку.
- Все входящие действия валидируются на сервере: текущая фаза, роль, право на действие и повторные запросы.
- Секретные роли и приватные действия никогда не рассылаются в общую комнату Socket.IO.
- Игровая логика должна быть отделена от транспортного слоя Socket.IO, чтобы её можно было тестировать независимо.

## Текущий MVP

Реализованы создание комнаты, вход по коду, список игроков, передача хоста при выходе создателя, готовность игроков, раздача ролей, ночные действия, приватная проверка комиссара, разрешение ночи, дневной чат, голосование, исключение игрока, автоматический переход к следующей ночи, таймеры фаз и проверка победы. При настроенном Redis комнаты и игровые сессии переживают перезапуск сервера; без Redis данные остаются в памяти процесса.

## Тестирование

Запустить `npm test` из корня репозитория. Сборка сервера выполняется перед запуском тестов. Автоматические unit-тесты проверяют состав колоды для 4–12 игроков, количество специальных ролей и мафии, условия победы города и мафии, продолжение партии, определение единственного лидера голосования, ничью, отсутствие голосов и независимость результата от порядка голосов. Интеграционный тест запускает настоящий сервер и четыре Socket.IO-клиента: создаёт комнату, подключает игроков, проверяет приватную раздачу ролей, выполняет ночные действия доктора, комиссара и мафии, проходит дневное голосование и проверяет победу города. GitHub Actions запускает оба вида тестов перед сборкой и публикацией клиента.
